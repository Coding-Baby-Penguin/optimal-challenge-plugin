# Native host workflow

This is the default for work inside Codex and Claude Code. Use the active host's
exposed tools, instructions and permissions. Read only the section needed for the
next decision. This skill gives workflow instructions, not an automatic controller.
The legacy Python resolver, numeric routing evaluator, registry and ledger apply
only when an explicitly selected controller/evaluation workflow actually uses them.
Do not manufacture adapter objects or require that absent bridge for ordinary work.

## Evidence and model choice

Identify the exact surface, client version, installed skill identity, model and effort
when a claim depends on them. Keep `documented`, `advertised`, `used`, `denied`,
`unavailable` and `unknown` separate. A catalog, successful CLI exit, or another
surface's success does not prove inference, permissions, enforcement or adoption.
Partial/paginated lists stay partial. Read back a supported override before claiming
it took effect; otherwise retain the active configuration and report the limitation.

GPT-6.1 Sol is `gpt-6.1-sol`. Codex/ChatGPT Work availability and host effort controls
are distinct from OpenAI API controls and ordinary ChatGPT Chat. Claude Code model
aliases, provider routes and login are distinct from Claude Desktop and the Anthropic
API. Choose the least capable available model adequate for the task; use stronger
reasoning only for a concrete difficult decision or a diagnosed failure. Do not change
global settings, buy acceleration, add API keys, or broaden access to fill a matrix.
See [supported surfaces](../../../docs/HOST-SUPPORT.md) for dated official sources.

## Smallest adequate execution

Continue the next unfinished approved action after checking source and ownership.
Keep coupled edits and shared-context sequential work with one implementer. Delegate
only when authorized, useful and supported; a slot or large model is not a reason.
Respect the user's worker limit and existing shared capacity. Reserve integration
and mandatory verification before optional work. Unknown capacity is not free.

For each actual handoff state: target goal/criterion, one outcome, allowed files and
tools, ownership, minimum evidence, ceiling/stop condition, and compact return.
Native role instructions do not create a sandbox. Codex workers inherit parent
sandbox/approvals; Claude plugin subagents cannot enforce permissionMode, hooks or
MCP-server frontmatter. Use supported host restrictions, and verify them before
security-dependent work. Never bypass approval or weaken a mandatory review.

## Resources and stop points

Use existing authorized shared and task limits, naming units, scope, observation time
and reset when known. No monetary ceiling or subscription percentage is invented.
A token/turn threshold is distinct from an account meter. Missing reset, attribution,
weights or counters remain unknown; API prices cannot convert subscription usage.

Account for coordinator/developer, workers, reviewers, retries, tools and monitoring.
Record available counters with session/task identity and whether cumulative. Deduplicate
replayed snapshots and difference monotonic cumulative counters within the same
session/reset; conflicting/decreasing counters require reconciliation. Cached input
is a subset of native input; reasoning is a subset of output. Do not add them twice.
Retain missing-role labels/reservations and identify proxy estimates. Neither this
instruction nor an observed counter proves an enforced provider cap.

At an authorized ceiling, start no new discretionary work, record `BUDGET_LIMIT`
and checkpoint unfinished/running work. Use only a supported safe stop primitive;
do not kill unrelated jobs. If required enforcement is unavailable, hold dependent
spend and obtain the needed route decision; do not silently accept advisory operation.

For a failing strategy, the default is one targeted retry with a new diagnosis or
materially new evidence, within the existing allocation. Then stop that strategy,
record `RETRY_LIMIT`, checkpoint and choose a smaller alternative or seek necessary
direction. After denial, retry at most once only with materially new authorization.
Inspect uncertain writes/results first; never replay completed side effects blindly.
Before any full-suite restart, reproduce/fix the specific failure, pass targeted
regressions, and verify harness inputs, dependencies, permissions and subject identity.
A missing required check is `UNKNOWN`/`BLOCKED`, never pass. No repeated broad loops.

## Checkpoint, recovery and review

Update the existing canonical state only at meaningful milestones, handoffs or limits.
Keep root goal, completed artifact/evidence pointers, relevant delta, failed/held checks,
remaining allocation/unknowns and one exact next action. Do not replay transcripts or
create competing state stores. On resume, inspect actual files, ownership and effects;
continue unfinished work. Native resume is optional: rehydrate from sufficient compact
state when unavailable; hold dependent work if evidence is insufficient. Cancellation,
partial completion and unknown terminal status must remain visible.

Use deterministic checks for reversible mechanical changes. Use one fresh independent
review for material judgment or when required. Bind the review to immutable source,
package/config identities and actual results; changed subjects require review of the
affected delta. Do not start review fleets or call self-review independent. Preserve
privacy/security approvals, failed evidence and release holds. Report useful outcomes,
escaped defects, missing roles and untested hosts; do not infer savings from token counts.
