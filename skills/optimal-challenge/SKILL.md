# Optimal Challenge

Route with minimum context and compute; authoritative instructions remain binding.

## Fast routing
1. Read the request, applicable instructions and unfinished state. Reuse an applicable approved plan. Replan only when invalidated, incomplete, or requested.
2. Use direct only when the task is stable, single-step, and low-risk and has no explicit team, exact-specialist, independent-review, or other non-inline routing constraint. Sequential work can remain with one implementer.
3. For substantive project work, read its own goal via [project goal](references/project-goal.md).
4. Before costly research, delegation, replanning, or review, load [context management](references/context-management.md) and run its goal-drift checkpoint. Cheap, reversible direct work is exempt.
5. When host capabilities, models, resources, delegation or recovery affect the route, use [native workflow](references/host-native.md). It takes precedence over legacy controller requirements for ordinary native work.

Only after rejecting direct work, load [premise validation](references/premise-validation.md) for material assumptions. For production with material scale, paid-generation, rejection, or rework risk, load [research before scale](references/high-cost-research.md).

Load [team orchestration](references/team-orchestration.md), [cost-quality routing](references/cost-quality-routing.md) and [team continuity](references/team-continuity.md) only for a real multi-workstream, explicit delegation or reuse decision. Mandatory safety, privacy and independent reviews remain binding.

## Conditional depth
For errors, timeouts, skipped checks, retries or unfinished work, load [failure visibility](references/failure-visibility.md) before reporting.

Load only what changes the next decision: [routing](references/routing.md), [reality](references/reality-model.md), [environment](references/environment-storage.md), [continuity](references/continuity-collaboration.md), [folders](references/folder-architecture.md), [configuration](references/configuration-governance.md), [README](references/readme-maintenance.md), [Codex](references/platform-codex.md), [Claude](references/platform-claude.md), [delegation](references/delegation-budget.md), [verification](references/verification.md), [simplification](references/simplification.md), [preferences](references/preference-model.md), [patterns](references/pattern-promotion.md), [evolution](references/evolution-policy.md), or [side effects](references/side-effects.md).

## Invariants
Existing valid work beats restarting. Thread length alone never justifies planning, delegation, or extra context. Escalations need information value and a stop condition. Never invoke `superpowers:using-superpowers`; select other skills only for a genuine unmet need.
