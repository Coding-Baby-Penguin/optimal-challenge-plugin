# Repository guide

Start with [CONTRIBUTING.md](CONTRIBUTING.md) for the exact environment and check command. [ARCHITECTURE.md](ARCHITECTURE.md) maps public entry points to their owners. [PROJECT-STATE.md](PROJECT-STATE.md) is the single current checkpoint; it distinguishes local structure, hosted CI, host behavior and release evidence. [CHANGELOG.md](CHANGELOG.md) records deliberate candidate changes without rewriting published history.

The stable user-authority and checkpoint guarantees are in [goal-context-contract.md](../config/goal-context-contract.md). The approved recovery sequence and frozen acceptance boundaries are in [the quality recovery plan](superpowers/plans/2026-09-29-holistic-quality-recovery.md); [the independent assessment](reviews/2026-09-29-independent-assessment.md) describes the historical subject. Treat plans and reviews as history, and consult current evidence before asserting an acceptance result.

Plugin runtime guidance starts at [SKILL.md](../skills/optimal-challenge/SKILL.md). Structural scenarios and acceptance contracts live under `tests/`; source checkers and compatibility commands live under `scripts/`. Generated archives belong in ignored `dist/`, raw host runs in ignored `tests/results/<evaluation-id>/`, local orchestration state in ignored `.optimal-challenge/`, and temporary dependencies/logs in ignored `tmp/quality/`. Never install from a dirty source checkout: the local marketplace installer can copy ignored scratch and `.git`; build and inspect a clean immutable release archive, then install from its extraction in an isolated host home.
