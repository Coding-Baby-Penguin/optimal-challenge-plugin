# Immutable evaluation subjects

The behavioral [run manifest](../../tests/evaluation-manifest.json) defines shared tasks, arm policies, host configuration and comparative margins. Each [subject manifest](../../tests/subjects/) independently pins its own archive and member hashes; neither an archive nor a subject manifest is embedded in itself. An archive SHA is a byte identity, while a Git commit, release tag, evaluation cachebuster label and installed registry entry answer different provenance questions. `scripts/verify_subject.py` requires the external subject manifest, an exact extracted source root, the archive and the actual isolated installed plugin root. It checks every archive member against the selected source and installed tree, including all available critical policy files. It rejects missing, extra, changed, duplicated, symlinked and unsafe members. Codex `plugin list --json` reports installed/enabled state, marketplace name, version and source path, but does not expose our arbitrary cachebuster label. Use distinct marketplace names and exact source/cache paths as the observable isolation keys; do not claim the label itself was read back.
