# Acceptance recording and observability

This is the local reviewed-import path for Task 6. Keep the acceptance manifest and each scored bundle separate from a recorder receipt, independent grader JSON, raw host JSON, and retained native event/rollout bytes. Raw artifacts belong only under an approved ignored `tests/results/<evaluation-id>/` directory. The importer accepts explicit local paths, hashes existing bytes and writes a receipt there; it never runs a model, fills missing answers, grades a result, or approves itself. Do not install a subject from a dirty checkout: build a deterministic archive, extract it cleanly, install in an isolated host home and read back critical installed bytes.

The current manifest names `codex-desktop` and `codex-local`. A Codex CLI `exec` rollout has `host_source=codex-cli` and cannot satisfy that desktop manifest, even if session metadata says “Codex Desktop.” Use a separately reviewed exact-surface manifest for CLI development/preflight; desktop acceptance remains unverified until desktop-native evidence exists. Record the exact host/CLI version, model, reasoning, installed archive/read-back, task/session identities, terminal state, wall time, tool events and complete whole-job native counters. The observed CLI JSON stream may omit `spawn_agent`; the rollout and child rollouts must be retained and audited. Child rollouts can inherit parent metadata, so count each own session once and use the last own cumulative counters. Do not infer semantic calculations from encrypted tool arguments or model claims.

For a one-task CLI recorder preflight, keep four small JSON files and the original native rollout files under an ignored local evidence directory. The preflight manifest has `preflight_version:1`, a disposable `task_id`, `host:codex-cli`, `surface:codex-cli-local`, `host_source:codex-cli`, exact `host_version`, `model`, `reasoning`, `subject_archive_sha256` from a clean immutable archive, and `installed_read_back` with verified installed critical-file digests. The raw JSON repeats those fields and adds `recorder_id`, root `session_id`, exact `output` text, `terminal_status:completed`, and the extracted whole-job `usage`, root `wall_seconds`, `tool_events` and `tool_events_complete`. A separate grader JSON has `grader_id`, `task_id`, SHA-256 of the raw file, SHA-256 of the exact output, an independently recorded `observed_result`, and `quality_claim:unverified`. The one-run bundle has `preflight_version:1`, `task_id`, SHA-256 of each manifest/raw/grade file, an ordered `native_rollout_sha256s` array, and `quality_claim:unverified`. File-byte hashes are calculated after each file is final; grade must be completed before the bundle. A grader identity field alone does not prove independence; the reviewer inspects the grading process.

Run `python scripts/codex_cli_rollout.py --rollout <root.jsonl> [--rollout <child.jsonl> ...] --output <new-audit.json>` and retain all original JSONL files plus the CLI JSON stream. The extractor rejects non-CLI sources, missing completion or counters, duplicate sessions, missing child parents and inconsistent usage. It reports `model_calls:null` because a native session may contain several model requests; this does not satisfy cost comparisons that require observed model-call counts. Then run `python scripts/verify_cli_preflight.py --manifest <manifest.json> --raw <raw.json> --grade <grade.json> --bundle <bundle.json> --rollout <root.jsonl> [--rollout <child.jsonl> ...]`. A `structurally_verified` result binds one CLI task's files and answer to its native bytes. Its quality and desktop acceptance fields remain `unverified`; this preflight is not an acceptance arm and cannot be compared with A or D.

The approved comparison tasks and grading masks are shared across all compared arms. Every arm retains valid poor outcomes, and universal safety, authority and control checks apply on every task. An arm-specific feature diagnostic is evaluated only where that feature is actually present; it cannot remove shared quality/cost or safety cases. The frozen case calculation is a structural case-spec check, never host semantic proof.

| Observation | Permitted source | Claim |
|---|---|---|
| Host task/session, installed bytes, exact output, terminal state, tool calls, spawn count, user-provided facts, native usage and wall time | Retained native event bytes plus independently audited extraction bound to their SHA-256 | Observed on that exact surface/version when complete |
| Typed routing or budget calculation | Actual trace containing its inputs, formula/version and result, independently compared with host behavior | Observed semantic diagnostic only when present |
| Expected utility, wrongness likelihood, hypothetical rework avoidance, unseen reasoning or encrypted tool arguments | No observable source | Unverified; do not invent values or ask the model to narrate them for quiet direct tasks |
| Canonical case inputs and expected formula outputs | Frozen acceptance fixture | Structural/case-spec diagnostic only |
| Quality, safety and task usefulness | Blind independent grader JSON bound to exact raw bytes and an audited grader roster | Reviewed outcome, separate from native measurements |

For each run, retain one raw JSON object, one independently authored grader JSON object and one native event/rollout file. The raw object must include the actual answer text plus the host/task/version/model/reasoning/install, terminal, complete usage, wall and tool-event fields. The grade binds the raw SHA and scores the same answer. `record_acceptance.py` takes `--bundle`, `--manifest`, `--evidence-root`, `--observations`, `--output`, and `--recorder-id`; observations list each `run_id`, unique `task_id`, and relative `raw_path`, `grade_path`, `native_path`. It refuses missing files, noncanonical/out-of-root paths and an existing receipt. Its output is an unapproved receipt, not verification.

An independent reviewer inspects the retained native bytes, confirms the recorder source and receipt origin, audits every native SHA and extracted task/session/version/terminal/usage/tool/output observation, and establishes a roster of graders independent of the recorder. Accepted native audit source identifiers are `codex-desktop-event-v1`, `codex-cli-rollout-v1` and `claude-code-event-v1` for their matching exact hosts; `synthetic-test-fixture` cannot enter production acceptance. A trusted local caller passes that audit to `register_recorder_review`; `verify_run_evidence` then validates the receipt, all raw/native/grader bytes and every scored run before issuing a process-local `VerifiedEvaluationContext`. `combine_verified_contexts` requires two distinct arms and rejects reused raw, grader, task, session or receipt identities. `compare_arms(..., evidence_context=context)` alone may upgrade the host outcome comparison; its separate `semantic_diagnostics` result remains `unverified` for every required case without an actual audited typed trace. A passed host outcome comparison does not erase that missing diagnostic or complete the final quality gate. Absent or stale context remains `unverified` and cannot expose an improvement claim.

Use `python scripts/review_acceptance.py --manifest <manifest> --baseline <bundle-A> --candidate <bundle-D> --baseline-receipt <receipt-A> --candidate-receipt <receipt-D> --audit <reviewed-audit> --evidence-root <local-root> --reviewer-id <independent-reviewer>` for the executable one-process comparison. The audit JSON maps arm IDs to `independent_graders` and per-run `native_audit`; the operator must inspect its source evidence and type the complete displayed input digest. The command then registers the reviewed inputs, verifies both arms, combines contexts and compares them in the same process. A CLI process that merely reads a review-status JSON does not recreate process-local approval. The release gate stays blocked until current subject identities and the complete release evidence are independently verified.

This trust model assumes an honest local reviewer and caller, local files that are retained through comparison, and code in the verifier process that has not been compromised. Hashes detect drift and bind files; they are not signatures against hostile same-process code. An imported status string, copied fixture output, self-declared `usage.complete`, or synthetic native file without a real audited origin cannot establish host behavior. Failed/cancelled runs, missing child usage, incomplete tool streams, grader disagreement or an unsupported surface remain explicit failed/blocked/unverified records. Retention is opt-in to the named local directory; never upload raw rollouts or credentials to structural CI. Preserve a sanitized index of digests, statuses, limitations and next actions for review.

The configuration loader accepts enforced budget mode only with a process-issued `VerifiedCapabilityContext` produced by `issue_config_capability_context` from matching, current, typed usage-counter and stop-primitive evidence that passed `resolve_capability` for the active surface/version. A caller-created dataclass or user JSON cannot authorize it. The issuance boundary still depends on an honest registered adapter and an actual observed executable stop handle; a caller-supplied `codex-host` string and allowlisted proof name in a unit fixture are insufficient. No current surface has an audited executable budget-stop adapter, so issuance fails closed for every current host.
