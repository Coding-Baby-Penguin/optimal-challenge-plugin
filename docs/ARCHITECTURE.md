# Maintainer architecture

`skills/optimal-challenge/SKILL.md` is the runtime router; its `references/` modules contain lazily loaded policy. `config/goal-context-contract.md` holds stable authority, goal and claim guarantees. `config/project.json` names the public commands and package exclusions. `docs/PROJECT-STATE.md` holds only the current checkpoint.

The public scripts remain stable entry points. `scripts/orchestration_state.py` re-exports ledger mutation from `scripts/optimal_challenge/ledger.py`, state validation from `state_validation.py`, and recovery/mandatory-reserve dispatch from `recovery.py`. `scripts/capability_matrix.py` re-exports the single proof-class objects and trusted issuance in `capability_evidence.py`, plus policy resolution and document checks in `capability_resolution.py`. `scripts/evaluate_behavior.py` retains the CLI and re-exports bundle validation from `evaluation_contracts.py`, statistics from `evaluation_statistics.py`, and comparison from `evaluation_comparison.py`; typed formula diagnostics belong to `evaluation_semantics.py` and are imported directly by internal tests.

`scripts/validate.py` integrates schema, routing, research, state, capability and behavioral-structure checks. `scripts/check_quality.py` runs the structural gate and writes explicit statuses. `scripts/package_release.py` selects tracked files and produces/verifies a deterministic archive. Source existence and a CI pass do not prove fresh-host behavior. The release gate requires independently bound host evidence and immutable installed identity; until that verifier and its receipts exist, release status remains blocked.

Tests in `tests/validation/` cover contract behavior, malformed inputs, facade identity, archive bytes and failure visibility. `tests/behavioral-acceptance.json` defines canonical host cases, while `tests/evaluation-manifest.json` pins comparison arms; their static expectations are not observations. Measured cost/latency comes from actual host counters, and unavailable measurements stay labelled. See [the move map](maintenance/folder-plan.md) for consumers and rollback boundaries.
